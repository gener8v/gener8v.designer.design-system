## ToolChip

Show an agent's tool call as a chip — running, then what it found.

**Use when**

- Each tool an agent calls inside a conversation: a pulse and what it is doing while it runs, the result once it lands.
- Refused and failed calls say so in a tag, in words; the arguments are a press away for the one reader who wants them.

**Not when**

- The call writes a change a person has to answer → `ConfirmCard`. Nothing should be written until the yes; a chip reports a call, it does not ask.
- The thing is a status label with nothing to open → `Tag` (status-and-feedback.md). A tag is a word for a state; a chip is a call with arguments and a result.
- The work is a long run with a count of parts, on a row of a list → `LiveProgress`. Live progress shows where the work is and how far it has got.

**Confused with** `ConfirmCard`, `Tag` (status-and-feedback.md), `LiveProgress`, `Live`

React `ToolChip` · hooks `toolWords` · classes `.tool-chip` · shown in `design/components/agent.html`

## ConfirmCard

Ask a person to confirm or approve a change an agent proposes, inline.

**Use when**

- An agent wants to write something: the card says the change, the values it will write, and who answers (`tier`). Nothing is written until the yes.
- A change that costs money: `spend` says so in a tag before the button, and the yes becomes Approve Spend.
- Once answered it stays as a record — the buttons go and the answer takes their place.

**Not when**

- The decision interrupts the whole page and has nothing to do with a conversation → `Dialog` (overlays.md). A dialog is modal and goes away when answered; a confirm card stays in the thread as the record.
- The person only needs to know something, not answer it → `Alert` (status-and-feedback.md). An alert reports; a confirm card asks and blocks the write until answered.
- The tool call has already run → `ToolChip`. A chip reports what a call did; a confirm card is for a change not yet made.

**Confused with** `Dialog` (overlays.md), `ToolChip`, `Alert` (status-and-feedback.md)

React `ConfirmCard` · classes `.confirm-card` · shown in `design/components/agent.html`

## Conversation

Show a person asking and a system answering, as it happens.

**Use when**

- A chat with an agent or assistant: `sent` turns are bubbles, `received` turns are prose at full measure. New turns are announced.
- `TurnPending` while waiting for the reply — it carries the word, because an animation is not an announcement.
- Tool calls and confirmations sit inside received turns as `ToolChip` and `ConfirmCard`.

**Not when**

- The record is an interview or meeting that nobody is adding to, with several speakers → `Transcript` (reading.md). A transcript is worked through and marked as evidence; a conversation is two-sided and live.
- People are leaving notes about a record → `Comment` (data.md). A comment is one authored note about something, with a time that matters.
- The history is who did what to a record, in order → `Feed` (data.md). A feed groups each person's run of actions; it is not an exchange.

**Confused with** `Transcript` (reading.md), `Comment` (data.md), `Feed` (data.md), `ToolChip`

React `Conversation`, `Turn`, `TurnPending` · classes `.conversation`, `.turn` · shown in `design/components/agent.html`

## Live

Show that work is happening right now, where the work is.

**Use when**

- `LiveIndicator` — a pulse with its words in a polite live region, "Agents working", at the head of a page or panel.
- `LiveMark` on a section heading, a `Contents` entry or a row; `LiveSection` around a part of a document being written.
- `Pulse` only beside words that already say the same thing — it is decorative and hidden from assistive tech.

**Not when**

- One row's progress with a count — `§2.5 ▬▬▬▭ 4/6` → `LiveProgress`. Live progress adds where, a bar and a count to the pulse, and becomes a tag when it finishes.
- Many items moving between waiting, working and done → `Lanes`. Lanes show the whole run by state; a pulse marks one place.
- A short wait with nothing running in the background → `Spinner` (status-and-feedback.md). A spinner is a control waiting; a pulse is work in progress somewhere the reader can look.
- A state that has settled — done, failed → `Tag` (status-and-feedback.md). A pulse means moving; a finished thing is a status word.

**Confused with** `LiveProgress`, `Lanes`, `Spinner` (status-and-feedback.md), `Tag` (status-and-feedback.md)

React `Pulse`, `LiveIndicator`, `LiveMark`, `LiveSection` · hooks `liveWhere` · classes `.live-pulse`, `.live-indicator`, `.live-mark`, `.live-section` · shown in `design/components/live.html`

## LiveProgress

Show one row's live work — where it is, how far, and how it ended.

**Use when**

- Under a title in a list or a table row while a run works on that item: pulse, place, bar and count.
- Queued, done and failed in the same slot, so a row does not change shape as the work moves.

**Not when**

- A single task with a percentage and no list around it → `Progress` (status-and-feedback.md). A progress bar is the bare measure; live progress is a row's whole live state.
- The whole run at a glance, by state → `Lanes`. Lanes show every item in its state; live progress sits on one row.
- A level that is simply true → `Meter` (data.md). A meter is not work advancing.

**Confused with** `Progress` (status-and-feedback.md), `Lanes`, `Live`, `ToolChip`

React `LiveProgress` · classes `.live-progress` · shown in `design/components/live.html`

## Lanes

Show many items of a run moving between waiting, working and done.

**Use when**

- An agent run seen by a reader: each agent a pill that slides from Waiting to Working to Done; `AGENT_LANES` are the defaults.
- Every lane says its count; arrivals in an `announce` lane are said once in a polite live region.

**Not when**

- One sequence of named steps → `Stepper` (status-and-feedback.md). A stepper is one path; lanes are many items sorted by state.
- One item's progress in a row → `LiveProgress`. A row carries its own live state; lanes are the overview.
- What happened, in order, after the run → `Timeline` (data.md). Lanes are now; a timeline is then.

**Confused with** `Stepper` (status-and-feedback.md), `LiveProgress`, `Live`, `Shelf` (input.md)

React `Lanes` · hooks `AGENT_LANES` · classes `.lanes`, `.lane` · shown in `design/components/live.html`
