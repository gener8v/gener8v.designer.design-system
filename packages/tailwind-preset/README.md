# @gener8v/tailwind-preset

Tailwind v4 `@theme` generated from the same tokens as the stylesheet, so utilities and the
component layer can never disagree.

```bash
npm i @gener8v/tailwind-preset     # private to the @gener8v npm org
```
```css
@import "tailwindcss";
@import "@gener8v/tailwind-preset/theme.css";
```

Then `bg-action`, `p-6`, `rounded-md`, `text-2xl` resolve to the system's values rather than
Tailwind's defaults.

## When to use a utility and when not to

**Prefer the semantic classes for anything the system already names.** `.btn`, `.card`,
`.tag`, `.panel`, `.field` — these carry states, focus treatment and accessibility styling
that a stack of utilities will not reproduce, and rebuilding a button out of `bg-action px-4
py-2 rounded-md` gets you something that looks like a button and behaves like a div.

Utilities are for **layout the system does not cover**: a one-off grid, a gap, a max-width on
a page section. That is the line.

## Why this exists at all

The system's own components use semantic classes, not utilities. This preset is here so a
consuming repo already standardised on Tailwind can lay out pages with familiar utilities
without hard-coding a single value — and so those utilities resolve to the same numbers the
components use. It is a bridge, not the primary interface.

## What is generated

Colours (every ramp step and role), spacing, the type scale, radii, shadows and motion — the
same values as `@gener8v/tokens`. `theme.css` is generated by `pnpm build:tokens`; never
hand-edit it, and CI will fail if you do.
